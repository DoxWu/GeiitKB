## 二、Task #144 收尾：监控配置补全

### 2.1 修改 `kb_qa_system/monitoring/docker-compose.monitoring.yml`

**目标**：添加 alertmanager 服务容器，使 Prometheus 告警能通过 Alertmanager 发送邮件通知。

**变更内容**：在 `grafana` 服务之后、`volumes:` 之前插入 alertmanager 服务定义：

```yaml
  # --------------------------------------------
  # Alertmanager 告警通知（D8-01）
  # --------------------------------------------
  # 作用：接收 Prometheus 触发的告警，通过邮件通知管理员
  # SMTP 配置复用项目 Resend 邮件服务（通过环境变量注入）
  alertmanager:
    image: prom/alertmanager:latest
    container_name: kb_qa_alertmanager
    restart: unless-stopped
    ports:
      - "9093:9093"
    volumes:
      - ./alertmanager.yml:/etc/alertmanager/alertmanager.yml:ro
    command:
      - "--config.file=/etc/alertmanager/alertmanager.yml"
      - "--storage.path=/alertmanager"
    # SMTP 配置通过环境变量注入（复用 Resend 配置）
    environment:
      ALERT_EMAIL_TO: ${ALERT_EMAIL_TO:-admin@example.com}
      ALERT_EMAIL_FROM: ${ALERT_EMAIL_FROM:-GeiIt企业知识库 <onboarding@resend.dev>}
      SMTP_HOST: ${SMTP_HOST:-smtp.resend.com}
      SMTP_PORT: ${SMTP_PORT:-465}
      SMTP_USER: ${SMTP_USER:-resend}
      SMTP_PASSWORD: ${SMTP_PASSWORD:-}
    depends_on:
      - prometheus
    networks:
      - default
```

同时更新文件头注释，在访问地址区域添加 `Alertmanager: http://localhost:9093`。

### 2.2 修改 `kb_qa_system/monitoring/prometheus.yml`

**目标**：添加 alerting 配置块，将触发的告警发送到 Alertmanager。

**变更内容**：在 `rule_files:` 之后、`scrape_configs:` 之前插入 alerting 配置：

```yaml
# 告警规则文件
rule_files:
  - "alerts.yml"

# 告警发送目标（D8-01 Alertmanager）
alerting:
  alertmanagers:
    - static_configs:
        - targets: ["alertmanager:9093"]

# 抓取目标
scrape_configs:
```

## 三、Task #145：回归测试与改进实施报告

### 3.1 新增测试文件

#### 3.1.1 创建 `kb_qa_system/backend/tests/test_cleanup_tasks.py`

**目标**：测试 cleanup_expired_data 任务的清理逻辑。

**测试用例**：
1. `test_cleanup_disabled_returns_skipped`：CLEANUP_ENABLED=False 时返回 skipped
2. `test_cleanup_enabled_executes_delete`：CLEANUP_ENABLED=True 时执行 4 表 DELETE 并返回统计
3. `test_cleanup_uses_correct_retention_days`：验证各表使用对应的 *_RETENTION_DAYS 配置
4. `test_cleanup_conversation_uses_is_active`：验证 Conversation 使用 is_active=false（非 is_deleted）
5. `test_cleanup_rollback_on_error`：异常时 rollback 并 raise

**实现方式**：monkeypatch `settings` 配置项 + mock `SessionLocal` 返回的 db 对象（mock execute/commit/rollback/close），验证 SQL 语句和参数。避免真实数据库依赖。

#### 3.1.2 创建 `kb_qa_system/frontend/src/utils/__tests__/highlight.test.tsx`

**目标**：测试 highlightKeyword 高亮函数。

**测试用例**：
1. `空关键词返回原文`：keyword 为空时返回 [text]
2. `匹配关键词高亮`：文本含关键词时返回 mark 元素
3. `大小写不敏感`：KEYWORD 匹配 keyword
4. `特殊字符转义`：关键词含正则特殊字符（如 `(`, `*`）不报错
5. `多处匹配`：多个匹配位置都被高亮

**实现方式**：使用 React Testing Library 的 render 验证 mark 元素渲染，或直接检查返回数组结构。
