## 实施步骤

### 步骤 1：创建 `frontend/src/pages/__tests__/ChatPage.test.tsx`

**作用**：ChatPage 页面级单元测试，覆盖布局渲染、空状态、消息列表、流式临时气泡、加载状态、错误条、mount 时加载对话列表。

**遵循模式**：参考 `ChatSidebar.test.tsx` 的 mock 模式。

**Mock 策略**：
- `vi.mock("@/store/chatStore")` → `useChatStore: () => mockChatStore`（返回普通对象）
- `vi.mock("@/store/authStore")` → `useAuthStore: () => mockAuthStore`
- `vi.mock("@/store/toastStore")` → `useToastStore: () => mockToastStore`
- 用 `MemoryRouter` 包裹（ChatPage 使用 `useParams`）

**测试用例**（约 8 个）：
1. 渲染布局：包含侧边栏（品牌"GeiIt企业知识库"）和主区域
2. mount 时调用 `loadConversations`
3. 空状态：messages 为空且非流式 → 显示"开始新对话"EmptyState
4. 加载状态：loadingMessages=true → 显示 Spinner（role="status"）
5. 消息列表：messages 数组 → 渲染对应数量的 MessageBubble
6. 流式临时气泡：streaming=true → 渲染临时 assistant 消息
7. 错误条：error 非空 → 显示错误文本
8. conversationId URL 参数：传入 `/chat/123` → 调用 selectConversation(123)

**实现要点**：
- `renderWithRouter(initialEntry)` 辅助函数：`<MemoryRouter initialEntries={[initialEntry]}><ChatPage /></MemoryRouter>`
- 每个测试前重置 `mockChatStore` 字段为默认空状态
- 第 8 个测试需用 `initialEntries={["/chat/123"]}` 并验证 `selectConversation` 被调用（由于 useEffect 异步，用 `vi.waitFor` 或直接断言 mock 被调用）

### 步骤 2：创建 `backend/tests/test_account_deletion.py`

**作用**：验证 `auth.py` 中 `delete_account` 端点的安全结构和合规逻辑（静态分析 + monkeypatch 行为测试）。

**遵循模式**：参考 `test_critical_fixes.py` 的 `read_source()` + 断言模式。

**测试类与用例**：

#### `TestAccountDeletionEndpoint` — 端点结构
1. `test_delete_route_exists`：auth.py 源码含 `@router.delete("/account"` 和 `async def delete_account`
2. `test_rate_limit_applied`：含 `rate_limit("account_delete", per_hour=3)` 依赖
3. `test_requires_auth`：含 `get_current_active_user` 依赖

#### `TestPasswordConfirmation` — 密码确认（防误操作 + CSRF）
4. `test_verifies_password`：含 `verify_password(body.password, current_user.hashed_password)`
5. `test_wrong_password_returns_401`：含 `HTTP_401_UNAUTHORIZED` + `INVALID_PASSWORD` 错误码

#### `TestPhysicalFileDeletion` — 物理文件删除（GDPR）
6. `test_queries_user_documents`：含 `db.query(Document).filter(Document.user_id == current_user.id)`
7. `test_deletes_files_from_upload_dir`：含 `os.path.join(settings.UPLOAD_DIR` + `os.remove(`
8. `test_file_deletion_failure_non_blocking`：含 `except OSError` + `logger.warning`（文件删除失败不阻塞）

#### `TestCascadeDeletion` — 级联删除
9. `test_deletes_user_record`：含 `db.delete(current_user)` + `db.commit()`
10. `test_db_failure_returns_500`：含 `except Exception` + `db.rollback()` + `HTTP_500_INTERNAL_SERVER_ERROR` + `DELETE_FAILED`
11. `test_qaevent_set_null_documented`：含 `SET NULL` 或 `匿名化` 注释（验证 QAEvent 保留匿名化统计）

#### `TestTokenRevocation` — Token 吊销
12. `test_extracts_access_token_from_header`：含 `Authorization` + `bearer ` 提取逻辑
13. `test_blacklists_access_token`：含 `blacklist_token(access_token)`
14. `test_blacklists_refresh_token_optional`：含 `body.refresh_token` 条件 + `blacklist_token(..., ttl=`

#### `TestAccountDeleteRequestSchema` — Schema 验证（行为测试，可导入 schemas.user 因为 pydantic 无重运行时依赖）
15. `test_password_required`：`AccountDeleteRequest()` 无 password 抛 ValidationError
16. `test_refresh_token_optional`：`AccountDeleteRequest(password="x")` 成功，refresh_token 默认 None
17. `test_password_max_length`：password 超 100 字符抛 ValidationError

**实现要点**：
- `read_source("app/api/routes/auth.py")` 读取路由源码
- Schema 测试用 `from app.schemas.user import AccountDeleteRequest` + `pytest.raises(ValidationError)`（pydantic 可独立导入）
- 若 `app.schemas.user` 导入失败（依赖链问题），降级为读取 `schemas/user.py` 源码断言 Field 定义

## 假设与决策

1. **后端测试不使用 TestClient**：遵循项目既有约定（静态分析 + monkeypatch），避免运行时依赖缺失导致测试失败。仅 Schema 测试尝试导入 pydantic 模块（无重依赖）。
2. **ChatPage 测试不测试真实交互**：mock store 的 actions 为 `vi.fn()`，验证被调用即可，不验证 store 状态变化（那是 chatStore.test.ts 的职责）。
3. **conversationId 参数测试**：由于 `useEffect` 依赖 `conversationId`，渲染后同步触发；用 `expect(selectConversation).toHaveBeenCalledWith(123)` 断言（React testing-library 会同步执行 effects）。
4. **验证顺序**：先 vitest（最可能暴露问题）→ tsc → build → pytest，失败即停并修复。
5. **报告语言**：中文，与项目其他文档一致。
