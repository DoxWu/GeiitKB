### 2.2 创建 `kb_qa_system/backend/app/tasks/cleanup_tasks.py`

**目标**：Celery 定时任务，每日凌晨 03:00 清理超过保留期的数据。

**设计决策**：
- Conversation：删除 `is_deleted=True` 且 `updated_at < now - CONVERSATION_RETENTION_DAYS` 的记录（仅清理已软删除的）
- QAEvent：删除 `created_at < now - QA_EVENT_RETENTION_DAYS` 的记录（日志型，物理删除）
- EmailLog：删除 `created_at < now - EMAIL_LOG_RETENTION_DAYS` 的记录
- AuditLog：删除 `created_at < now - AUDIT_LOG_RETENTION_DAYS` 的记录
- `CLEANUP_ENABLED=False` 时跳过执行（允许环境级关闭）

**文件内容框架**：
```python
"""
数据清理任务（D10-03 数据保留策略）

作用：
    Celery 定时任务，每日凌晨 03:00 执行，清理超过保留期的数据：
    - 已软删除的对话（is_deleted=True 且超过保留期）
    - 过期的 QA 事件日志
    - 过期的邮件发送日志
    - 过期的审计日志

实现方式：
    1. 由 Celery beat 调度（crontab hour=3, minute=0）
    2. 根据 config.py 中的 *_RETENTION_DAYS 配置计算截止时间
    3. 分批删除避免长事务锁表
    4. 记录清理统计到日志
"""
from datetime import datetime, timedelta, timezone
from celery import shared_task
from celery.utils.log import get_task_logger
from sqlalchemy import text

from app.core.config import settings
from app.core.database import SessionLocal

logger = get_task_logger(__name__)


@shared_task(name="app.tasks.cleanup_tasks.cleanup_expired_data")
def cleanup_expired_data() -> dict:
    """
    清理过期数据（定时任务）

    作用：
        按保留策略删除过期数据，防止数据库无限膨胀。

    返回：
        dict - 各表删除统计 {"conversations": n, "qa_events": n, ...}
    """
    if not settings.CLEANUP_ENABLED:
        logger.info("数据清理已关闭（CLEANUP_ENABLED=False），跳过执行")
        return {"skipped": True, "reason": "CLEANUP_ENABLED=False"}

    now = datetime.now(timezone.utc)
    stats = {}

    db = SessionLocal()
    try:
        # 1. 清理已软删除的对话
        cutoff = now - timedelta(days=settings.CONVERSATION_RETENTION_DAYS)
        result = db.execute(text(
            "DELETE FROM conversations WHERE is_deleted = true AND updated_at < :cutoff"
        ), {"cutoff": cutoff})
        stats["conversations"] = result.rowcount

        # 2. 清理 QA 事件日志
        cutoff = now - timedelta(days=settings.QA_EVENT_RETENTION_DAYS)
        result = db.execute(text(
            "DELETE FROM qa_events WHERE created_at < :cutoff"
        ), {"cutoff": cutoff})
        stats["qa_events"] = result.rowcount

        # 3. 清理邮件日志
        cutoff = now - timedelta(days=settings.EMAIL_LOG_RETENTION_DAYS)
        result = db.execute(text(
            "DELETE FROM email_logs WHERE created_at < :cutoff"
        ), {"cutoff": cutoff})
        stats["email_logs"] = result.rowcount

        # 4. 清理审计日志
        cutoff = now - timedelta(days=settings.AUDIT_LOG_RETENTION_DAYS)
        result = db.execute(text(
            "DELETE FROM audit_logs WHERE created_at < :cutoff"
        ), {"cutoff": cutoff})
        stats["audit_logs"] = result.rowcount

        db.commit()
        logger.info(f"数据清理完成: {stats}")
        return stats

    except Exception as e:
        db.rollback()
        logger.error(f"数据清理失败: {e}", exc_info=True)
        raise
    finally:
        db.close()
```

**注意**：表名需与实际模型表名一致。需在实现时确认 `Conversation.__tablename__`（应为 `conversations`）、`QAEvent.__tablename__`（应为 `qa_events`）、`EmailLog.__tablename__`（应为 `email_logs`）、`AuditLog.__tablename__`（应为 `audit_logs`）。

## 三、Task #139：前端改进

### 3.1 D5-01 IME 输入法组合事件处理

**文件**：`frontend/src/components/documents/SearchBar.tsx`、`frontend/src/components/chat/ChatInput.tsx`

**问题**：中文/日文输入法组合过程中（compositionstart → compositionend），每次按键都会触发 onChange/onSubmit，导致输入未完成就被提交或搜索。

**方案**：添加 `isComposing` 状态锁，composition 期间不触发搜索/提交。

**SearchBar.tsx 变更**：
```tsx
const [isComposing, setIsComposing] = useState(false);

// 输入框添加事件
<input
  ...
  onCompositionStart={() => setIsComposing(true)}
  onCompositionEnd={(e) => {
    setIsComposing(false);
    // composition 结束后触发一次搜索
    handleSearch(e.currentTarget.value);
  }}
  onChange={(e) => {
    setQuery(e.target.value);
    if (!isComposing) {
      handleSearch(e.target.value);
    }
  }}
  onKeyDown={(e) => {
    if (e.key === 'Enter' && !isComposing) {
      e.preventDefault();
      handleSearch(query);
    }
  }}
/>
```

**ChatInput.tsx 变更**：同模式，composition 期间 Enter 键不提交。

### 3.5 D2-02 搜索结果高亮

**文件**：
- 创建 `frontend/src/utils/highlight.ts`（高亮工具函数）
- 修改 `frontend/src/components/documents/SearchBar.tsx` 或文档列表组件（在高亮处使用）

**highlight.ts**：
```typescript
/**
 * 高亮搜索关键词
 * @param text 原始文本
 * @param keyword 关键词
 * @returns React 节点数组（匹配部分用 <mark> 包裹）
 */
export function highlightKeyword(text: string, keyword: string): React.ReactNode[] {
  if (!keyword.trim()) return [text];
  const regex = new RegExp(`(${escapeRegExp(keyword)})`, 'gi');
  return text.split(regex).map((part, i) =>
    regex.test(part) ? <mark key={i} className="bg-yellow-200">{part}</mark> : part
  );
}
```

# D3-01 内容安全策略（CSP）
# 作用：限制资源加载来源，防御 XSS 攻击
# 注意：script-src 'self' 允许同源脚本；connect-src 需包含后端 API 域名
add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; font-src 'self' data:; connect-src 'self' https://*.up.railway.app; object-src 'none'; base-uri 'self'; frame-ancestors 'self'" always;

- `img-src data:`：允许 base64 图片（如头像占位）
