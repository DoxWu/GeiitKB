## 1. 认证与用户管理

### 1.1 注册申请

| 项目 | 说明 |
|------|------|
| **功能描述** | 用户通过邮箱申请注册账号，需输入两次邮箱地址（一致性校验防输入错误），提交后由管理员审批 |
| **实现方式** | 后端 API：`app/api/routes/registration.py`；前端页面：`RegisterApplyPage.tsx`；邮件服务：`app/services/email_service.py`（Resend SMTP） |
| **核心逻辑** | 1. 前端两次邮箱输入一致性校验<br>2. 后端检查邮箱是否已注册<br>3. 创建注册申请记录（status=pending）<br>4. 发送通知邮件给管理员<br>5. 管理员审批后发送密码设置链接 |
| **输入输出** | **输入**：`{email, email_confirm, reason}`<br>**输出**：`{message: "申请已提交"}` |
| **关键配置** | `EMAIL_ENABLED`、`SMTP_HOST`、`SMTP_PORT`、`ADMIN_NOTIFY_EMAIL`、`PASSWORD_TOKEN_EXPIRE_HOURS=24` |

### 1.2 密码设置

| 项目 | 说明 |
|------|------|
| **功能描述** | 管理员审批注册申请后，系统发送含 token 的密码设置链接，用户通过链接设置密码 |
| **实现方式** | 后端：`registration.py` 路由 + `email_service.py`；前端：`SetPasswordPage.tsx` |
| **核心逻辑** | 1. Token 生成：`secrets.token_urlsafe(32)`（256 位熵）<br>2. Token 存储：SHA-256 哈希后存数据库（不存明文）<br>3. 一次性使用：设置密码后立即失效<br>4. 24 小时过期<br>5. 限流：每小时最多 5 次 |
| **输入输出** | **输入**：`{token, password, password_confirm}`<br>**输出**：`{message: "密码设置成功"}` |
| **关键配置** | `PASSWORD_TOKEN_EXPIRE_HOURS=24`、Token 限流 5 次/小时 |

### 1.3 用户登录

| 项目 | 说明 |
|------|------|
| **功能描述** | 支持用户名和邮箱两种方式登录，返回 JWT Access Token 和 Refresh Token |
| **实现方式** | 后端：`app/api/routes/auth.py`；前端：`LoginPage.tsx` + `authStore.ts`（Zustand） |
| **核心逻辑** | 1. 同时查询 `User.username` 和 `User.email`（前端 email 字段作为 username 发送）<br>2. 密码 bcrypt 校验<br>3. 登录失败计数 + 锁定（5 次失败锁定 15 分钟）<br>4. 签发 JWT（Access 15 分钟，Refresh 7 天） |
| **输入输出** | **输入**：`{username, password}`（username 字段可填邮箱）<br>**输出**：`{access_token, refresh_token, token_type, user: {id, username, email, user_type}}` |
| **关键配置** | `ACCESS_TOKEN_EXPIRE_MINUTES=15`、`REFRESH_TOKEN_EXPIRE_DAYS=7`、`LOGIN_FAILURE_LOCK_THRESHOLD=5`、`LOGIN_FAILURE_LOCK_MINUTES=15`、`UserLogin.username` max_length=100（支持邮箱长度） |

### 1.4 游客登录（临时登录）

| 项目 | 说明 |
|------|------|
| **功能描述** | 提供游客登录入口，无需注册即可体验，但限制为 20 次提问，仅可访问公共文档库，不可上传文档 |
| **实现方式** | 后端：`auth.py` guest-login 路由 + `chat.py` 提问计数 + `documents.py` 上传限制；前端：`LoginPage.tsx` 游客按钮 + `authStore.ts` |
| **核心逻辑** | 1. 创建 guest 类型用户（`user_type='guest'`）<br>2. Redis 计数器：`guest:questions:{user_id}`，TTL 24 小时<br>3. 每次提问成功后 +1，达到 20 次返回 429<br>4. 文档上传/URL 导入接口用 `get_current_regular_user` 依赖保护（guest 被拒） |
| **输入输出** | **输入**：无（一键登录）<br>**输出**：`{access_token, user: {user_type: "guest"}}` |
| **关键配置** | Guest 提问上限 20 次、Redis TTL 24 小时、`user_type` 字段（regular/guest） |

### 1.5 Token 刷新与登出

| 项目 | 说明 |
|------|------|
| **功能描述** | Access Token 过期后用 Refresh Token 获取新的 Access Token；登出时使 Token 失效 |
| **实现方式** | 后端：`auth.py` refresh/logout 路由 |
| **核心逻辑** | 1. Refresh Token 校验有效性<br>2. 签发新的 Access Token<br>3. 登出时将 Token 加入 Redis 黑名单（TTL = Token 剩余有效期） |
| **输入输出** | **输入**：`{refresh_token}`<br>**输出**：`{access_token, token_type}` |
| **关键配置** | `SECRET_KEY`、`ALGORITHM=HS256`、Redis 黑名单 TTL |

## 2. 文档管理

### 2.1 文档上传

| 项目 | 说明 |
|------|------|
| **功能描述** | 用户上传 PDF/Word/Markdown/TXT 文件到个人或公共文档库，触发异步处理流水线 |
| **实现方式** | 后端：`app/api/routes/documents.py` upload_document；前端：`DocumentsPage.tsx` + `api/document.ts`；异步任务：`app/tasks/document_tasks.py` process_document_task |
| **核心逻辑** | 1. 文件类型和大小校验<br>2. 保存到 uploads 目录<br>3. 创建 Document 记录（status=pending）<br>4. 派发 Celery 异步处理任务<br>5. guest 用户被拒（`get_current_regular_user` 依赖） |
| **输入输出** | **输入**：`multipart/form-data: {file, visibility, folder_id?}`<br>**输出**：`{id, title, status: "pending", ...}` |
| **关键配置** | `ALLOWED_FILE_TYPES=[.pdf, .md, .txt, .markdown, .docx]`、`MAX_FILE_SIZE=50MB`、`UPLOAD_DIR=./uploads`、`RATE_LIMIT_UPLOAD_PER_HOUR=20` |

### 2.2 URL 导入

| 项目 | 说明 |
|------|------|
| **功能描述** | 通过 URL 导入网页内容，流式下载并解析为知识库文档 |
| **实现方式** | 后端：`documents.py` import_from_url；解析器：`app/services/document_pipeline/url_parser.py` |
| **核心逻辑** | 1. URL 格式校验<br>2. 流式下载（累计字节数，超限中止）<br>3. HTML → 纯文本转换<br>4. 创建 Document 记录并触发处理流水线<br>5. guest 用户被拒 |
| **输入输出** | **输入**：`{url, visibility, folder_id?}`<br>**输出**：`{id, title, status: "pending"}` |
| **关键配置** | `URL_IMPORT_MAX_SIZE=50MB` |

### 2.3 文档列表与筛选

| 项目 | 说明 |

| **功能描述** | 分页查询文档列表，支持按文件夹、可见性、状态、关键词筛选 |

## 3. 文档处理流水线

### 3.1 文档解析

| 项目 | 说明 |
|------|------|
| **功能描述** | 解析 PDF/DOCX/MD/TXT 文件，提取文本内容和结构化信息 |
| **实现方式** | 模块：`app/services/document_pipeline/`；解析器：PDF（pdfplumber）、DOCX（python-docx）、MD/TXT（直接读取） |
| **核心逻辑** | 1. 根据文件类型选择解析器<br>2. PDF：逐页提取文本+页码<br>3. DOCX：段落+表格提取<br>4. MD：保留 Markdown 语法<br>5. 输出 PipelineContext（含 pages/tables/images） |
| **输入输出** | **输入**：文件路径<br>**输出**：`PipelineContext {pages, tables, images, cleaned_text}` |
| **关键配置** | `ENABLE_OCR=True`、`ENABLE_VISION=True`、`ENABLE_TABLE_EXTRACTION=True` |

### 3.2 OCR 图片识别

| 项目 | 说明 |
|------|------|
| **功能描述** | 识别扫描件 PDF 中的文字，将图片转为可检索文本 |
| **实现方式** | 模块：`app/services/document_pipeline/ocr_processor.py`；引擎：Tesseract / 云服务 |
| **核心逻辑** | 1. 检测 PDF 是否为扫描件（文本层是否为空）<br>2. 渲染页面为图片<br>3. OCR 识别文字<br>4. 识别结果作为页面文本 |
| **输入输出** | **输入**：PDF 页面图片<br>**输出**：`{text, confidence}` |
| **关键配置** | `ENABLE_OCR=True` |

### 3.3 多模态图片理解

| 项目 | 说明 |
|------|------|
| **功能描述** | 用多模态 LLM 理解文档中的图片内容，生成文字描述用于检索 |
| **实现方式** | 模块：`app/services/document_pipeline/`；模型：`VISION_MODEL_NAME` |
| **核心逻辑** | 1. 提取文档中的图片<br>2. 调用多模态 LLM 生成图片描述<br>3. 描述作为独立 chunk 参与检索 |
| **输入输出** | **输入**：图片二进制<br>**输出**：`{description, image_data}` |
| **关键配置** | `ENABLE_VISION=True`、`VISION_MODEL_NAME=gpt-4o-mini` |

### 3.4 表格结构化提取

| 项目 | 说明 |
|------|------|
| **功能描述** | 提取文档中的表格，转为 Markdown 格式作为独立 chunk |
| **实现方式** | 模块：`app/services/document_pipeline/` |
| **核心逻辑** | 1. 检测文档中的表格<br>2. 提取表格结构和数据<br>3. 转为 Markdown 表格语法<br>4. 表格作为独立块（不切分） |
| **输入输出** | **输入**：文档表格<br>**输出**：`ExtractedTable {markdown, rows, caption}` |
| **关键配置** | `ENABLE_TABLE_EXTRACTION=True` |

### 3.5 LaTeX 公式保护

| 项目 | 说明 |
|------|------|
| **功能描述** | 分块前用占位符替换 LaTeX 公式（`$$...$$` 和 `$...$`），分块后恢复，避免公式被截断 |
| **实现方式** | 模块：`app/services/document_pipeline/latex_protector.py` |
| **核心逻辑** | 1. 正则匹配 `$$...$$` 和 `$...$`<br>2. 替换为占位符 `LATEX_PLACEHOLDER_N`<br>3. 分块器对占位符文本切分<br>4. 分块后恢复占位符为原始公式 |
| **输入输出** | **输入**：含 LaTeX 的文本<br>**输出**：`{protected_text, placeholders: {placeholder: formula}}` |
| **关键配置** | `ENABLE_LATEX_PROTECTION=True` |

### 3.6 智能分块

| 项目 | 说明 |
|------|------|
| **功能描述** | 将清洗后的文本切分为合适大小的块（chunk），用于后续向量化 |
| **实现方式** | 模块：`app/services/document_pipeline/chunker.py`；工具：`RecursiveCharacterTextSplitter`（LangChain） |
| **核心逻辑** | 1. 递归分隔符：`\n\n` → `\n` → `。` → `.` → `！` → `？` → `；` → `;` → 空格 → 字符<br>2. 表格独立成块（不切分）<br>3. 图片描述独立成块<br>4. 每块携带元数据（页码、字符位置、块类型）<br>5. chunk_index 统一编号 |
| **输入输出** | **输入**：`PipelineContext {cleaned_text, tables, images}`<br>**输出**：`List[ProcessedChunk]`（text/table/image 类型） |
| **关键配置** | `CHUNK_SIZE=800`（任务3调整）、`CHUNK_OVERLAP=100`（任务3调整）、分隔符列表 |

### 3.7 向量化嵌入

| 项目 | 说明 |
|------|------|
| **功能描述** | 将文本块转为向量，存入 pgvector 数据库用于相似度检索 |
| **实现方式** | 模块：`app/services/vector_store.py`；嵌入服务：OpenAI API（主）+ 本地模型（兜底） |
| **核心逻辑** | 1. 调用 Embedding API 将文本转为向量<br>2. 主服务不可用时降级到本地模型（BAAI/bge-small-zh-v1.1）<br>3. 向量存入 document_chunks 表的 embedding 列（vector(1536)）<br>4. 阿里云 text-embedding-v4 需传 `dimensions=1536` 参数 |
| **输入输出** | **输入**：`List[ProcessedChunk]`<br>**输出**：写入 `document_chunks` 表（含 embedding 向量） |
| **关键配置** | `EMBEDDING_MODEL_NAME`、`EMBEDDING_DIMENSION=1536`、`LOCAL_EMBEDDING_MODEL=BAAI/bge-small-zh-v1.1`、`EMBEDDING_TIMEOUT=15` |

## 4. 对话问答

### 4.1 非流式问答

| 项目 | 说明 |
|------|------|
| **功能描述** | 用户提问，系统检索知识库文档片段，调用 LLM 生成回答，返回引用来源 |
| **实现方式** | 后端：`app/api/routes/chat.py` ask_question；服务：`app/services/rag_chain.py` RAGChainService.ask() |
| **核心逻辑** | 1. 意图识别（kb_query → 检索；chitchat/followup/meta → 无检索）<br>2. Query 改写（指代消解+语义扩展）<br>3. 检索文档片段（retrieve_context）<br>4. 预生成校验（避免无相关文档时浪费 LLM 调用）<br>5. 构建 Prompt（系统提示词+上下文+历史+问题）<br>6. 调用 LLM 生成回答<br>7. 矛盾检测（标记冲突片段）<br>8. 保存对话记录+QA 事件 |
| **输入输出** | **输入**：`{conversation_id, question}`<br>**输出**：`{answer, sources: [{document_id, title, content, score}], question, intent, metrics}` |
| **关键配置** | `SYSTEM_PROMPT`、`ENABLE_QUERY_REWRITE=True`、`ENABLE_CONFLICT_DETECTION=True`、`RATE_LIMIT_ASK_PER_MINUTE=20` |

### 4.2 流式问答（SSE）

| 项目 | 说明 |
|------|------|
| **功能描述** | 流式输出回答（Server-Sent Events），逐字返回提升用户体验 |
| **实现方式** | 后端：`chat.py` ask_question_stream；服务：`rag_chain.py` ask_stream()；FastAPI StreamingResponse |
| **核心逻辑** | 1. 同非流式的检索流程<br>2. LLM 流式输出（逐 token 返回）<br>3. SSE 格式：`data: {"content": "..."}\n\n`<br>4. 流式结束后保存完整回答<br>5. **陷阱**：流式生成器后处理阶段需创建独立 SessionLocal()（请求级 session 可能已失效） |
| **输入输出** | **输入**：`{conversation_id, question}`<br>**输出**：SSE 流（`data: {content}\n\n` 格式） |
| **关键配置** | `LLM_STREAM_FIRST_TOKEN_TIMEOUT=30`（推理模型需调大）、流式后处理独立 session |

### 4.3 多轮对话（历史上下文）

| 项目 | 说明 |
|------|------|

## 5. 检索系统

### 5.1 向量检索（pgvector）

| 项目 | 说明 |
|------|------|
| **功能描述** | 将用户问题向量化，在 pgvector 中检索相似度最高的文档片段 |
| **实现方式** | 服务：`app/services/vector_store.py` vector_search()；数据库：PostgreSQL + pgvector 扩展 |
| **核心逻辑** | 1. 用户问题 → Embedding 向量<br>2. SQL：`SELECT *, embedding <=> :query_vector AS distance FROM document_chunks WHERE document_id IN (...) ORDER BY distance LIMIT :k`<br>3. `<=>` 操作符为余弦距离<br>4. 距离转换为相似度分数：`score = 1 - distance` |
| **输入输出** | **输入**：`{query, top_k, document_ids}`<br>**输出**：`[{chunk_id, content, score, document_id, metadata}]` |
| **关键配置** | `EMBEDDING_DIMENSION=1536`、`SIMILARITY_THRESHOLD=0.35`（任务3调整）、pgvector `vector(1536)` 列类型 |

### 5.2 关键词检索（PostgreSQL 全文检索）

| 项目 | 说明 |
|------|------|
| **功能描述** | 用 PostgreSQL 全文检索（tsvector + tsquery）进行关键词匹配 |
| **实现方式** | 服务：`vector_store.py` keyword_search()；索引：GIN 索引 |
| **核心逻辑** | 1. 用户问题 → tsquery（`to_tsquery('simple', :query)`）<br>2. 文档内容 → tsvector（`to_tsvector('simple', content)`）<br>3. `ts_rank` 计算相关度<br>4. GIN 索引加速匹配<br>5. **注意**：`ts_rank` 必须用与索引定义一致的表达式 `to_tsvector('simple', dc.content)`，不能用 `content_tsv` 列 |
| **输入输出** | **输入**：`{query, top_k, document_ids}`<br>**输出**：`[{chunk_id, content, keyword_score, document_id}]` |
| **关键配置** | GIN 索引建在 `to_tsvector('simple', content)` 表达式上 |

### 5.3 混合检索（加权融合）

| 项目 | 说明 |
|------|------|
| **功能描述** | 结合向量检索和关键词检索，加权融合两路结果 |
| **实现方式** | 服务：`vector_store.py` search() |
| **核心逻辑** | 1. 并行执行向量检索和关键词检索<br>2. 按 chunk_id 合并结果<br>3. 加权计算：`final_score = vector_score × vector_weight + keyword_score × keyword_weight`<br>4. 按 final_score 排序<br>5. 降级：向量检索无结果时回退到仅关键词检索 |
| **输入输出** | **输入**：`{query, top_k, document_ids, keyword_weight}`<br>**输出**：融合排序后的结果列表 |
| **关键配置** | `ENABLE_HYBRID_SEARCH=True`、`KEYWORD_SEARCH_WEIGHT=0.3`（默认）、`candidate_k = top_k × 3` |

### 5.4 动态权重（intent_classifier 复用）★ 任务2新增

| 项目 | 说明 |
|------|------|
| **功能描述** | 根据查询子类型动态调整向量/关键词检索权重，替代静态的 0.7/0.3 分配 |
| **实现方式** | 服务：`intent_classifier.py` `_detect_query_sub_type()` + `rag_chain.py` `retrieve_context()` + `vector_store.py` `search(keyword_weight=...)` |
| **核心逻辑** | 1. `intent_classifier._detect_query_sub_type(query)` 纯正则检测子类型（零延迟）：<br>   - EXACT_MATCH：含代码标识符/错误码/引号/版本号 → keyword_weight=0.6<br>   - SEMANTIC：含"如何/为什么/区别/原理" → keyword_weight=0.2<br>   - HYBRID：默认 → keyword_weight=0.3<br>2. `settings.QUERY_SUBTYPE_WEIGHTS` 映射子类型到权重<br>3. 透传 `keyword_weight` 参数给 `vector_store.search()`<br>4. `vector_store.search()` 内部：`vector_weight = 1 - keyword_weight` |
| **输入输出** | **输入**：query 文本<br>**输出**：QuerySubType 枚举值（exact_match/semantic/hybrid） |
| **关键配置** | `QUERY_SUBTYPE_WEIGHTS={"exact_match": 0.6, "semantic": 0.2, "hybrid": 0.3}`（任务2新增） |

### 5.5 Reranking 重排序

| 项目 | 说明 |
|------|------|
| **功能描述** | 用 cross-encoder 对向量检索的候选结果二次打分，提升 Top-K 精确度 |
| **实现方式** | 服务：`app/services/reranker.py`；模型：sentence-transformers CrossEncoder |
| **核心逻辑** | 1. 向量检索召回 `top_k × multiplier` 个候选<br>2. cross-encoder 对每个 (query, chunk) 对打分<br>3. 按分数排序取 final_top_k<br>4. 原理：双塔模型（向量检索）快但精度有限，交互模型（cross-encoder）精度高但慢 |
| **输入输出** | **输入**：`{query, results, top_k}`<br>**输出**：重排序后的 top_k 结果 |
| **关键配置** | `ENABLE_RERANKING=True`、`RERANKER_MODEL_NAME=BAAI/bge-reranker-base`、`RERANKER_CANDIDATE_MULTIPLIER=5`（任务3调整） |

### 5.6 权限隔离检索

| 项目 | 说明 |
|------|------|
| **功能描述** | 检索范围限定为用户有权访问的文档（自己的 + 公共库），防止越权 |
| **实现方式** | 服务：`rag_chain.py` `_compute_search_scope()` + `app/services/permission.py` |

| **关键配置** | `user_type` 字段（regular/guest）、permission_service |
