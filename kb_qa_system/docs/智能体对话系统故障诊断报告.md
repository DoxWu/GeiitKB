# 智能体对话系统故障诊断与修复报告

> **报告日期**：2026-07-12
> **故障现象**：智能体对话系统持续生成失败，前端提示"降级回复 · 智能体响应失败：抱歉，回答生成过程中出现错误，请稍后重试"
> **修复状态**：✅ 已修复，全部 5 个场景测试通过

---

## 一、故障现象

用户在使用智能体对话系统时，所有提问均返回错误提示：

> 降级回复 · 智能体响应失败：抱歉，回答生成过程中出现错误，请稍后重试

该错误**持续出现**，非偶发性问题，严重影响系统可用性。

---

## 二、诊断方法论

采用**分层诊断法**，从调用链顶层（前端错误提示）逐层向下追踪到根因：

```
前端错误提示
  └→ 后端 SSE error 事件 (chat.py:559)
      └→ event_stream() except 块捕获的异常
          └→ 逐层检查：LLM 调用 → RAG 链 → 检索层 → 后处理 DB 操作
```

诊断工具：
- `test_chat_debug.py`：容器内 RAG 链直接调用测试（绕过 HTTP 层）
- `test_multi_scenario.py`：HTTP/SSE 端到端多场景测试（模拟前端调用路径）
- Docker 日志分析：精确定位异常堆栈和行号

---

## 三、根因分析

经全面诊断，发现**4 个独立缺陷**叠加导致故障，按调用链顺序如下：

### 缺陷 1：`rag_chain.py` 缺少 `import threading`（致命根因）

| 项目 | 详情 |
|------|------|
| **文件** | `app/services/rag_chain.py` |
| **位置** | 第 25 行（缺失） / 第 1758 行（使用处） |
| **现象** | `NameError: name 'threading' is not defined` |
| **影响** | `get_rag_chain()` 完全无法初始化，**所有**对话请求 100% 失败 |

**根因**：模块级代码 `_rag_chain_lock = threading.Lock()` 在模块加载时执行，但 `import threading` 未在文件顶部导入。M-13 修复添加了线程锁但遗漏了导入语句。

**调用链**：
```
chat.py event_stream() → get_rag_chain() → 模块加载 → _rag_chain_lock = threading.Lock()
                                                          → NameError（threading 未导入）
```

### 缺陷 2：`vector_store.py` 向量检索 `SET LOCAL` 绑定参数错误

| 项目 | 详情 |
|------|------|
| **文件** | `app/services/vector_store.py` |
| **位置** | 第 310 行 |
| **现象** | `syntax error at or near "$1"` |
| **影响** | 向量检索全部失败，知识库问答无法检索文档 |

**根因**：PostgreSQL `SET LOCAL` 语句**不支持绑定参数**（`:probes`），必须使用字面量插值。原代码 `db.execute(text("SET LOCAL ivfflat.probes = :probes"), {"probes": ...})` 导致语法错误。

### 缺陷 3：`vector_store.py` 关键词检索 `ts_rank` 类型错误

| 项目 | 详情 |
|------|------|
| **文件** | `app/services/vector_store.py` |
| **位置** | 第 433、436 行 |
| **现象** | `function ts_rank(text, tsquery) does not exist` |
| **影响** | 关键词检索全部失败 |

**根因**：迁移脚本将 `content_tsv` 列创建为 `Text` 类型（非 `tsvector`），但 GIN 索引建在 `to_tsvector('simple', content)` 表达式上。`ts_rank(dc.content_tsv, ...)` 传入的是 `text` 类型，无匹配函数签名。

### 缺陷 4：`vector_store.py` 向量检索缺少 `threshold` 参数

| 项目 | 详情 |
|------|------|
| **文件** | `app/services/vector_store.py` |
| **位置** | 第 350 行 |
| **现象** | `A value is required for bind parameter 'threshold'` |
| **影响** | 向量检索 SQL 执行失败 |

**根因**：SQL 中添加了 `:threshold` 占位符但 `params["threshold"]` 从未赋值。

### 缺陷 5：`chat.py` 后处理 DB session 失效（HTTP 端错误事件根因）

| 项目 | 详情 |
|------|------|
| **文件** | `app/api/routes/chat.py` |
| **位置** | `event_stream()` 第 502 行 |
| **现象** | `InvalidRequestError: Instance '<Conversation>' is not persistent within this Session` |
| **影响** | LLM 正确生成回答后，后处理（保存消息/记录埋点/生成摘要）抛异常，触发 error 事件 |

**根因**：FastAPI `StreamingResponse` 中，请求级 `Depends(get_db)` 的 session 在生成器后处理阶段可能已失效（依赖清理时机问题），导致 `conversation` ORM 对象脱离 session，`db.refresh(conversation)` 抛 `InvalidRequestError`。

**表现特征**：LLM 实际已正确生成回答（前端可见完整回复），但 `done` 事件后仍发送 `error` 事件。

### 缺陷 6：熔断器阈值过低导致误熔断

| 项目 | 详情 |
|------|------|
| **文件** | `.env` / `.env.example` |
| **现象** | Aliyun 端点间歇性 SSL EOF 错误，阈值 5 次即熔断 |
| **影响** | 主 LLM 端点被熔断器拦截（降级到 DeepSeek 仍可用，但非最优） |

**根因**：阿里云 MAAS 端点存在间歇性 `[SSL: UNEXPECTED_EOF_WHILE_READING]` 网络错误，原阈值 5 次过低，短时间内的间歇性失败即触发熔断。

## 四、修复方案

### 修复 1：添加 `import threading`（缺陷 1）

**文件**：`app/services/rag_chain.py`

```python
# 修复前（第 23-26 行）
import logging
import re
from typing import List, Dict, Any, Optional, AsyncGenerator

# 修复后
import logging
import re
import threading  # 新增：M-13 线程锁依赖
from typing import List, Dict, Any, Optional, AsyncGenerator
```

### 修复 2：`SET LOCAL` 使用字面量插值（缺陷 2）

**文件**：`app/services/vector_store.py` 第 310 行

```python
# 修复前
db.execute(text("SET LOCAL ivfflat.probes = :probes"), {"probes": settings.IVFFLAT_PROBES})

# 修复后（int 校验后字面量插值，杜绝 SQL 注入）
probes_value = int(settings.IVFFLAT_PROBES)
assert probes_value > 0, "IVFFLAT_PROBES 必须为正整数"
db.execute(text(f"SET LOCAL ivfflat.probes = {probes_value}"))
```

### 修复 3：关键词检索使用 `content` 列匹配 GIN 索引（缺陷 3）

**文件**：`app/services/vector_store.py` 第 433、436 行

```sql
-- 修复前（content_tsv 是 Text 类型，ts_rank 不接受）
ts_rank(dc.content_tsv, to_tsquery('simple', :tsquery))
WHERE dc.content_tsv @@ to_tsquery('simple', :tsquery)

-- 修复后（使用 content 列 + to_tsvector 表达式，匹配 GIN 索引）
ts_rank(to_tsvector('simple', dc.content), to_tsquery('simple', :tsquery))
WHERE to_tsvector('simple', dc.content) @@ to_tsquery('simple', :tsquery)
```

### 修复 4：补全 `threshold` 绑定参数（缺陷 4）

**文件**：`app/services/vector_store.py` 第 351 行

```python
# 修复前（SQL 有 :threshold 但 params 未赋值）
sql += " AND 1 - (dc.content_vector <=> :query_vector) >= :threshold"

# 修复后
sql += " AND 1 - (dc.content_vector <=> :query_vector) >= :threshold"
params["threshold"] = settings.SIMILARITY_THRESHOLD
```

### 修复 5：后处理使用独立 DB session（缺陷 5）

**文件**：`app/api/routes/chat.py` `event_stream()` 函数

**核心思路**：在 `event_stream()` 内部创建独立的 `SessionLocal()` 进行后处理 DB 操作，不依赖请求级 `Depends(get_db)` session，彻底规避 StreamingResponse 中的 session 生命周期问题。

```python
# 修复要点：
# 1. 流式生成器前捕获纯值（conv_id, user_id_val, question_text）
conv_id = conversation.id
user_id_val = current_user.id
question_text = question_data.question

# 2. event_stream() 内部使用独立 session
async def event_stream():
    ...
    # 后处理使用独立 session
    from app.core.database import SessionLocal as _SessionLocal
    post_db = _SessionLocal()
    try:
        assistant_message = Message(conversation_id=conv_id, ...)
        post_db.add(assistant_message)
        _increment_turn_count(post_db, conv_id)
        post_db.commit()
        post_db.refresh(assistant_message)

        # 重新查询 conversation（独立 session 中的持久实例）
        fresh_conv = post_db.query(Conversation).filter(
            Conversation.id == conv_id
        ).first()

        # QA 埋点 + 摘要生成都使用 post_db
        qa_event_service.record_event(db=post_db, ...)
        if fresh_conv is not None:
            history_service.maybe_generate_summary(post_db, fresh_conv)
    finally:
        post_db.close()
```

同时为 `_increment_turn_count` 的批量 UPDATE 添加 `synchronize_session=False`：
```python
db.execute(
    update(Conversation)
    .where(Conversation.id == conversation_id)
    .values(turn_count=Conversation.turn_count + 1)
    .execution_options(synchronize_session=False)
)
```

### 修复 6：调高熔断器阈值（缺陷 6）

**文件**：`.env` / `.env.example`

```env
# 修复前
```

## 七、经验总结

1. **`import` 完整性检查**：添加新的模块级代码（如 `threading.Lock()`）时，必须确认对应 import 已存在。建议使用 linter（如 ruff/flake8）自动检测未定义名称。

2. **PostgreSQL `SET LOCAL` 不支持绑定参数**：这是 PostgreSQL 的语法限制，`SET`/`SET LOCAL` 语句必须是字面量。对于整型配置值，`int()` 校验 + f-string 插值是安全的做法。

3. **迁移脚本列类型与索引一致性**：`content_tsv` 列定义为 `Text` 但 GIN 索引建在 `to_tsvector('simple', content)` 表达式上，导致查询时类型不匹配。应确保查询使用与索引定义一致的表达式。

4. **FastAPI StreamingResponse + Depends 的 session 生命周期**：`StreamingResponse` 的生成器在流式发送期间执行，请求级 `Depends(get_db)` session 可能在后处理阶段失效。**标准模式**：在生成器内部创建独立的 `SessionLocal()` 进行 DB 操作。

5. **熔断器阈值调优**：对于存在间歇性网络错误（如 SSL EOF）的 API 端点，阈值过低会导致误熔断。应根据错误频率合理设置阈值（本项目 5→10）。

6. **分层诊断法**：面对"持续失败"类问题，从调用链顶层逐层向下追踪，使用诊断脚本绕过 HTTP 层直接测试核心服务，能快速区分"传输层问题"与"核心服务问题"。
